*asciidoc.nvim.txt*    AsciiDoc support for Neovim

==============================================================================
INTRODUCTION                                              *asciidoc.nvim*

AsciiDoc support for Neovim 0.11+: syntax highlighting, folding, text objects,
section motions, concealed markup, and a ready-made setup for asciidoc-lsp. No setup() call is
needed.

==============================================================================
REQUIREMENTS                                    *asciidoc.nvim-requirements*

- Neovim >= 0.11
- nvim-treesitter (for `:TSInstall`)
- a current asciidoc-lsp in `$PATH` (for LSP features)
- inotify-tools on Linux (recommended, see |asciidoc.nvim-file-watching|)

Install parsers after plugin setup: >
    :TSInstall asciidoc asciidoc_inline
<
After each plugin update, update them from an AsciiDoc buffer (see
|asciidoc.nvim-parser-pin|): >
    :TSUpdate asciidoc asciidoc_inline
<

==============================================================================
INSTALLATION                                    *asciidoc.nvim-installation*

Lazy.nvim (minimal): >lua
    {
        'seflue/asciidoc.nvim',
        ft = 'asciidoc',
        dependencies = { 'nvim-treesitter/nvim-treesitter' },
    }
<

Lazy.nvim (with overrides): >lua
    {
        'seflue/asciidoc.nvim',
        ft = 'asciidoc',
        dependencies = { 'nvim-treesitter/nvim-treesitter' },
        init = function()
            vim.g.asciidoc = {
                treesitter = { auto_install = true },
            }
            vim.lsp.config('asciidoc', {
                cmd = { '/custom/path/asciidoc-lsp' },
            })
            vim.lsp.enable('asciidoc')
        end,
    }
<

==============================================================================
CONFIGURATION                                  *asciidoc.nvim-configuration*

                                                          *vim.g.asciidoc*
Plugin settings via `vim.g.asciidoc`. No `setup()` call needed.

Default values: >lua
    vim.g.asciidoc = {
        treesitter = {
            -- Install missing parsers and rebuild ones built from
            -- another revision, see |asciidoc.nvim-parser-pin|
            auto_install = false,
            -- Grammar source per parser, see |asciidoc.nvim-parser-pin|
            asciidoc = nil,  -- { url = ..., branch = ..., revision = ... }
                             -- or { path = ... }
            asciidoc_inline = nil,
        },
        textobjects = {
            enable = true,  -- `iS` / `aS`, see |asciidoc.nvim-textobjects|
        },
        motions = {
            enable = true,  -- section motions, see |asciidoc.nvim-motions|
            keys = {        -- false leaves a key unmapped
                next = "]]", prev = "[[",
                next_sibling = "][", prev_sibling = "[]",
                parent = "[u", next_parent = "]u",
            },
        },
        folds = {
            enable = true,  -- Tree-sitter folds, see |asciidoc.nvim-folds|
        },
        conceal = {
            enable = true,  -- hide inline delimiters, see |asciidoc.nvim-conceal|
        },
    }
<

                                                    *asciidoc.nvim-lsp*
LSP config uses Neovim 0.11 native defaults (`lsp/asciidoc.lua`).
Override with `vim.lsp.config()` before enabling: >lua
    vim.lsp.config('asciidoc', {
        cmd = { '/custom/path/asciidoc-lsp' },
        settings = { ... },
    })
    vim.lsp.enable('asciidoc')
<
The plugin ignores the semantic tokens asciidoc-lsp sends for editors
without a Tree-sitter highlighter: they would be drawn over the Tree-sitter
highlights (|lsp-semantic-highlight|). `lsp/asciidoc.lua` does this in
`on_init`. If you set your own `on_init`, it replaces that one: add >lua
    client.server_capabilities.semanticTokensProvider = nil
<
                                              *asciidoc.nvim-file-watching*
The LSP config lets `asciidoc-lsp` watch `.asciidoctorconfig` and `.adoc`
files (`workspace.didChangeWatchedFiles.dynamicRegistration`), so changes
on disk (another editor, `git checkout`) reach the server without a
restart. On Linux, install `inotify-tools`: without
`inotifywait`, Neovim falls back to a watcher that reports changes in
the workspace root but none in subdirectories. To turn watching off: >lua
    vim.lsp.config('asciidoc', {
        capabilities = {
            workspace = { didChangeWatchedFiles = { dynamicRegistration = false } },
        },
    })
<
A complete `capabilities` table that includes Neovim's defaults (for
example from |vim.lsp.protocol.make_client_capabilities()| or a completion
plugin) turns watching off as well: on Linux and BSD those defaults set
`dynamicRegistration = false`. Set it to `true` in that table to keep
watching.

TREESITTER                                        *asciidoc.nvim-treesitter*

The plugin registers the seflue AsciiDoc grammars with nvim-treesitter:

- `asciidoc`: block-level grammar (sections, blocks, macros)
- `asciidoc_inline`: inline grammar (bold, italic, links, xrefs)

Inline content is injected via `injections.scm` (paragraph lines).
Source blocks take their language from `[source,<lang>]`, diagram
blocks from their style (e.g. `[mermaid]`).

                                                 *asciidoc.nvim-parser-pin*
The bundled queries are written for one tree-sitter-asciidoc commit, and
the plugin pins both parsers to it (`lua/asciidoc/grammar.lua`). A parser
built from another commit can lack a node the queries name; Neovim then
rejects the whole query file and, for `highlights.scm`, highlights
nothing. nvim-treesitter rebuilds a pinned parser on `:TSUpdate` once the
pin differs from the revision it was built from, but `:TSInstall` skips a
parser that is already installed. So after each plugin update run, with
an AsciiDoc buffer open (nvim-treesitter only knows the parsers once the
plugin is loaded): >
    :TSUpdate asciidoc asciidoc_inline
<
and restart Neovim, which keeps a loaded parser for the session.
`:checkhealth asciidoc` reports a parser the queries do not fit, see
|asciidoc.nvim-health|.

With `auto_install = true` the plugin does this itself when it loads (on
nvim-treesitter's `main` branch): it installs missing parsers and updates
those nvim-treesitter built from another revision. On nvim-treesitter's
`master` branch it only warns.

To build from another source, override it per parser: >lua
    vim.g.asciidoc = {
        treesitter = {
            asciidoc = {
                url = 'https://github.com/you/tree-sitter-asciidoc',
                branch = 'my-fix',
            },
            asciidoc_inline = { revision = '<full commit SHA>' },
        },
    }
<
`revision` replaces the pin and must be a full commit SHA. A `url` or
`branch` override without `revision` drops the pin, because
nvim-treesitter prefers a revision to a branch and a fork may not contain
the pinned commit. `url` must be a GitHub-style remote: nvim-treesitter
downloads `<url>/archive/<revision or branch>.tar.gz`. For a local
checkout set `path` to the repository root instead; nvim-treesitter then
builds the checkout as it is, without a pin: >lua
    asciidoc = { path = '/path/to/tree-sitter-asciidoc' },
<
Without a pin, `:TSUpdate` does not rebuild the parser; reinstall it with
`:TSInstall! asciidoc asciidoc_inline`.

QUERIES                                            *asciidoc.nvim-queries*

Bundled queries in `queries/asciidoc/` and `queries/asciidoc_inline/`:

  `highlights.scm`     Syntax highlighting (block + inline)
  `folds.scm`          Section and block folding
  `injections.scm`     Inline injection + source block languages
  `textobjects.scm`    Section/block selection (nvim-treesitter-textobjects)

Block textobjects (requires nvim-treesitter-textobjects):
  `vab` / `vib`        Select around/inner delimiter block

Section text objects are mapped by the plugin itself, see
|asciidoc.nvim-textobjects|.

TEXT OBJECTS                                    *asciidoc.nvim-textobjects*

                                                        *asciidoc.nvim-iS*
                                                        *asciidoc.nvim-aS*
In AsciiDoc buffers the plugin maps two section text objects in Visual and
Operator-pending mode (buffer-local):

  `iS`    inside section: the content below the heading
  `aS`    around section: the heading with its content, including block
          anchors and attributes above the heading

Both select whole lines and take the innermost section around the cursor
(in Visual mode: around the top of the selection), nested sections
included. With a count they take the section that many levels out, so
`2aS` in a subsection selects its parent. Outside any section, past the
outermost one, or for `iS` on a section that is only a heading, they
select nothing and cancel a pending operator; repeating with |.| there
reports "No section here". Examples: `daS` deletes a section, `yiS`
yanks its content, `.` repeats on the section under the cursor.

They use the bundled `textobjects.scm` query (`@section.inner`,
`@section.outer`) through |vim.treesitter| and need the `asciidoc` parser
only. They work with or without mini.ai and nvim-treesitter-textobjects.
The plugin does not map the sentence objects |is| and |as|.

With mini.ai, `a` and `i` are mapped globally as well: type `S` within
'timeoutlen', otherwise mini.ai takes the `a` or `i` and rejects `S`.

To turn them off: >lua
    vim.g.asciidoc = { textobjects = { enable = false } }
<
Set this before the plugin loads (for example in lazy.nvim's `init`).

SECTION MOTIONS                                    *asciidoc.nvim-motions*

In AsciiDoc buffers the plugin maps six section motions in Normal, Visual
and Operator-pending mode (buffer-local):

                                                        *asciidoc.nvim-]]*
  `]]`    next section, of any level
                                                        *asciidoc.nvim-[[*
  `[[`    previous section, of any level: from body text the title of the
          section whose content began last before the cursor, which may be
          a subsection
                                                        *asciidoc.nvim-][*
  `][`    next sibling: the next section with the same parent
                                                        *asciidoc.nvim-[]*
  `[]`    previous sibling
                                                        *asciidoc.nvim-[u*
  `[u`    enclosing section: from body text the title of the section the
          cursor is in, from a title (or the anchors and attributes above
          it) the title of its parent
                                                        *asciidoc.nvim-]u*
  `]u`    next section at the level `[u` goes to: the next sibling of the
          section `[u` would reach, so from a title the parent's next
          sibling

The head of a section, its title with the block anchors and attributes
above it, counts as the section's start: from any of these lines `]]`
goes to the section after it and `[[` to the one before.

`][`, `[]`, `[u` and `]u` start from the innermost section around the cursor,
so they act the same on a title and in the text below it. `][` at the
last sibling and `[]` at the first find nothing; they never move to
another level.

A count repeats the motion: `3]]` jumps three sections ahead, `2[u` two
levels out (like `2aS`), `2]u` two levels out and then to the next
sibling. Without a target, also when the count reaches
past the last one, the cursor stays and "No section here" is reported;
the motions do not wrap around the ends of the document.

In Normal and Visual mode they land in column 0 of the title line and set
the previous context mark, so |CTRL-O| jumps back. Visual mode extends the
selection. After an operator the motion is exclusive and ends at the
start of the target section, including its block anchors and attributes
above the title: `d]]` deletes up to the next section and keeps its
anchor. Without a target the operator is cancelled. |.| resolves the
motion again from the cursor.

Sections are the `section` nodes of the `asciidoc` parser, as the bundled
`textobjects.scm` query captures them (`@section.outer`), and nest as the
grammar nests them, also across a skipped level. Headings inside
delimited blocks, discrete headings (`[discrete]`, `[float]`) and the
document title are no targets, so `[u` and `]u` on a top-level title
find nothing.

nvim-orgmode uses `]]` / `[[` for headlines of the same level and `}` /
`{` for any level; here `]]` / `[[` take any level and `][` / `[]` the
same one. vim-markdown, where these keys come from, has `]u` for the
parent; here that is `[u`, so `[` goes back and `]` forward.

To change a key, or turn one off with `false`: >lua
    vim.g.asciidoc = { motions = { keys = { parent = "gh", next = false } } }
<
To turn all of them off: >lua
    vim.g.asciidoc = { motions = { enable = false } }
<
Set this before the plugin loads (for example in lazy.nvim's `init`).

FOLDS                                                *asciidoc.nvim-folds*

In AsciiDoc buffers the plugin sets 'foldmethod' to `expr` and 'foldexpr'
to `v:lua.vim.treesitter.foldexpr()` (window-local). The bundled
`folds.scm` folds sections and delimited blocks (listing, literal,
example, open, sidebar, passthrough, quote and comment blocks), tables and
lists. An admonition paragraph (`NOTE: ...`) does not fold; its block form
(`[NOTE]` with `====`) does. A section fold starts at the section title,
so an anchor or attribute line above it stays visible.

The plugin does not set 'foldlevel': with Neovim's default of 0 a file
opens with every fold closed, and |zR| opens them all. To open files
unfolded, set 'foldlevelstart', for example `vim.o.foldlevelstart = 99`.
To leave the fold options alone: >lua
    vim.g.asciidoc = { folds = { enable = false } }
<

==============================================================================
CONCEAL                                            *asciidoc.nvim-conceal*

The plugin conceals the delimiters of strong, italic, monospace and
highlighted text, single and doubled: `*strong*`, `__italic__`, monospace
in backticks, `#highlight#`. The text keeps its highlighting. In
`[.role]#text#` the role stays visible. Superscript (`^x^`), subscript
(`~x~`) and passthrough (`+x+`) keep their delimiters, which are the only
mark of them in a terminal.

Neovim's own options decide what is shown: nothing is hidden at
'conceallevel' 0, the delimiters disappear at 2, and 'concealcursor'
decides whether the cursor line shows them (by default it does). The
plugin sets neither option. To turn concealing off: >lua
    vim.g.asciidoc = { conceal = { enable = false } }
<

HEALTH CHECK                                    *asciidoc.nvim-health*

Run `:checkhealth asciidoc` to verify the setup. Checks:

1. Neovim version >= 0.11
2. The `asciidoc-lsp` command is executable and its version is at least
   the one the plugin requires. Warns when the version cannot be read.
3. Treesitter ABI version
4. Treesitter parser `asciidoc` installed
5. Treesitter parser `asciidoc_inline` installed
6. Every query file Neovim loads for `asciidoc` and `asciidoc_inline`
   (bundled or your own) loads with the installed parser. Reports each
   file that does not, with the hint to run
   `:TSUpdate asciidoc asciidoc_inline` and restart Neovim.
7. The revision nvim-treesitter built each parser from matches the pin or
   your `revision` override. Warns otherwise; skipped for parsers
   nvim-treesitter did not build and for overrides without `revision`.
8. nvim-treesitter plugin available (optional)
9. Every loaded asciidoc buffer with `asciidoc-lsp` attached: buffer path,
   client name and `root_dir`. Warns when the buffer path is not the file's
   real path (opened through a symlink).
10. `inotifywait` executable (Linux only), see
   |asciidoc.nvim-file-watching|.

DEBUGGING                                          *asciidoc.nvim-debug*

                                                          *:AsciidocDebug*
:AsciidocDebug
    Ask `asciidoc-lsp` how it resolves the cursor position in the current
    buffer (`asciidoc.explainPosition`) and show the report as Markdown in
    a scratch buffer. The report lists the raw and canonical file path, the
    workspace root, the reference under the cursor, how it resolves (per
    scope for attributes) and the known attributes with their
    source. Each call replaces the report in the same buffer and window.
    Line breaks in reported values appear as `\n` and `\r`.

PREVIEW                                          *asciidoc.nvim-preview*

                                                        *:AsciidocPreview*
:AsciidocPreview [{mode}]
    Ask `asciidoc-lsp` to start the preview of the current buffer and open
    the returned URL in the browser (|vim.ui.open()|). The server needs
    `asciidoctor` in `$PATH`; an error from the server is shown with
    |vim.notify()|. From then on the plugin sends the cursor line to the
    server on |CursorMoved|, |CursorMovedI| and |BufEnter| in AsciiDoc
    buffers of the same client, at most every 100 ms, and the page scrolls
    to it. Nothing is sent before the command has succeeded.

    The page also works towards the editor; both can be switched off in
    the page:
    - Scrolling the page puts the line on its reading line, a quarter
      down the page, at the top of the window (`asciidoc/revealLine`), in
      the current buffer only. Nothing happens when that line is already
      at the top; the cursor moves only as far as the new view needs, and
      that move is not sent back to the page.
    - When a chapter of an included file crosses the reading line, the
      cursor goes to its `include::` line; at the top and the end of the
      page it goes to the first and the last line.
    - A double-click on a block opens its source line, also in another
      file (`window/showDocument`, Neovim's own handler). Neovim cannot
      bring the terminal to the front; switch to it yourself.

                                                  *:AsciidocPreview-mode*
    The optional {mode} (completed with <Tab>) selects what the page shows:

    `document`  the complete document this buffer belongs to (default)
    `part`      only the part this buffer contributes, for example an
                included file

    Any other value is reported as an error and nothing is sent.

                                                 *:AsciidocPreview-debug*
:AsciidocPreview debug {action}
    The scroll-sync debug log of the open preview, for when the page
    scrolls somewhere else than the cursor. Off by default. {action}:

    `on`    the server numbers each cursor line it sends, and the page
            reports how it placed each one: the two anchors the line lies
            between (source line, page Y and the class of the block, or
            `synthetic`), the target, the action and the scroll position
            before and after. The page shows the last report in a box.
    `off`   stop numbering and reporting; the log stays.
    `show`  open the last 50 cursor lines with the page's reports in a
            split, as a markdown table.

    With `ASCIIDOC_LSP_LOG=debug` the server also writes both sides to its
    log. Without an open preview the server's error is shown.

                                                   *:AsciidocPreview-toc*
:AsciidocPreview toc {mode}
    The table of contents of the open preview, for every page of it; the
    page's TOC select follows. The document and the build stay as they
    are. {mode} (completed with <Tab>):

    `auto`   the default: the document's `:toc: left` or `:toc: right`;
             otherwise a sidebar on the left if the document has more than
             one level-1 section and more than five of level 2 or deeper,
             else none. Decided when the preview shows a document or the
             document's own `:toc:` changes, not on every change.
    `off`    no table of contents.
    `left`   a sidebar on the left.
    `right`  a sidebar on the right.

    A missing or unknown {mode} is reported as an error and nothing is
    sent. Without an open preview the server's error is shown.

                                                    *:AsciidocPreviewStop*
:AsciidocPreviewStop
    Stop sending the cursor line for the client of the current buffer. The
    page in the browser stays as it is and the preview server keeps
    running; |:AsciidocPreview| makes the page follow again. Without an
    open preview this only shows an info message. The autocommands and the
    throttle timer are removed once no client follows any more. If the
    browser cannot be opened, |:AsciidocPreview| reports the error and the
    page does not follow.
