*asciidoc.nvim.txt*    AsciiDoc support for Neovim

==============================================================================
INTRODUCTION                                              *asciidoc.nvim*

Batteries-included AsciiDoc plugin for Neovim 0.11+.
Provides LSP client config, Treesitter grammar registration, syntax queries,
buffer settings, filetype detection, and health checks — zero-config.

==============================================================================
REQUIREMENTS                                    *asciidoc.nvim-requirements*

- Neovim >= 0.11
- nvim-treesitter (for `:TSInstall`)
- asciidoc-lsp binary in `$PATH` (for LSP features)
- inotify-tools on Linux (recommended, see |asciidoc.nvim-file-watching|)

Install parsers after plugin setup: >
    :TSInstall asciidoc asciidoc_inline
<

==============================================================================
INSTALLATION                                    *asciidoc.nvim-installation*

Lazy.nvim (minimal, zero-config): >lua
    {
        'user/asciidoc.nvim',
        ft = 'asciidoc',
        dependencies = { 'nvim-treesitter/nvim-treesitter' },
    }
<

Lazy.nvim (with overrides): >lua
    {
        'user/asciidoc.nvim',
        ft = 'asciidoc',
        dependencies = { 'nvim-treesitter/nvim-treesitter' },
        init = function()
            vim.g.asciidoc = {
                treesitter = { auto_install = true },
            }
            vim.lsp.config('asciidoc', {
                cmd = { '/custom/path/asciidoc-lsp' },
            })
            vim.lsp.enable('asciidoc')
        end,
    }
<

==============================================================================
CONFIGURATION                                  *asciidoc.nvim-configuration*

                                                          *vim.g.asciidoc*
Plugin settings via `vim.g.asciidoc`. No `setup()` call needed.

Default values: >lua
    vim.g.asciidoc = {
        treesitter = {
            auto_install = false,  -- auto-install parsers if missing
        },
        textobjects = {
            enable = true,  -- `iS` / `aS`, see |asciidoc.nvim-textobjects|
        },
    }
<

                                                    *asciidoc.nvim-lsp*
LSP config uses Neovim 0.11 native defaults (`lsp/asciidoc.lua`).
Override with `vim.lsp.config()` before enabling: >lua
    vim.lsp.config('asciidoc', {
        cmd = { '/custom/path/asciidoc-lsp' },
        settings = { ... },
    })
    vim.lsp.enable('asciidoc')
<

                                              *asciidoc.nvim-file-watching*
The LSP config lets `asciidoc-lsp` watch `.asciidoctorconfig` and `.adoc`
files (`workspace.didChangeWatchedFiles.dynamicRegistration`), so changes
on disk (another editor, `git checkout`) reach the server without a
restart. On Linux, install `inotify-tools`: without
`inotifywait`, Neovim falls back to a watcher that reports changes in
the workspace root but none in subdirectories. To turn watching off: >lua
    vim.lsp.config('asciidoc', {
        capabilities = {
            workspace = { didChangeWatchedFiles = { dynamicRegistration = false } },
        },
    })
<
A complete `capabilities` table that includes Neovim's defaults (for
example from |vim.lsp.protocol.make_client_capabilities()| or a completion
plugin) turns watching off as well: on Linux and BSD those defaults set
`dynamicRegistration = false`. Set it to `true` in that table to keep
watching.

==============================================================================
TREESITTER                                        *asciidoc.nvim-treesitter*

The plugin registers the seflue AsciiDoc grammars with nvim-treesitter:

- `asciidoc` — block-level grammar (sections, blocks, macros)
- `asciidoc_inline` — inline grammar (bold, italic, links, xrefs)

Inline content is injected via `injections.scm` (paragraph lines).
Source blocks take their language from `[source,<lang>]`, diagram
blocks from their style (e.g. `[mermaid]`).

==============================================================================
QUERIES                                            *asciidoc.nvim-queries*

Bundled queries in `queries/asciidoc/` and `queries/asciidoc_inline/`:

  `highlights.scm`     Syntax highlighting (block + inline)
  `folds.scm`          Section and block folding
  `injections.scm`     Inline injection + source block languages
  `textobjects.scm`    Section/block selection (nvim-treesitter-textobjects)

Block textobjects (requires nvim-treesitter-textobjects):
  `vab` / `vib`        Select around/inner delimiter block

Section text objects are mapped by the plugin itself, see
|asciidoc.nvim-textobjects|.

==============================================================================
TEXT OBJECTS                                    *asciidoc.nvim-textobjects*

                                                        *asciidoc.nvim-iS*
                                                        *asciidoc.nvim-aS*
In AsciiDoc buffers the plugin maps two section text objects in Visual and
Operator-pending mode (buffer-local):

  `iS`    inside section: the content below the heading
  `aS`    around section: the heading with its content, including block
          anchors and attributes above the heading

Both select whole lines and take the innermost section around the cursor
(in Visual mode: around the top of the selection), nested sections
included. With a count they take the section that many levels out, so
`2aS` in a subsection selects its parent. Outside any section, past the
outermost one, or for `iS` on a section that is only a heading, they
select nothing and cancel a pending operator; repeating with |.| there
reports "No section here". Examples: `daS` deletes a section, `yiS`
yanks its content, `.` repeats on the section under the cursor.

They use the bundled `textobjects.scm` query (`@section.inner`,
`@section.outer`) through |vim.treesitter| and need the `asciidoc` parser
only. They work with or without mini.ai and nvim-treesitter-textobjects.
The plugin does not map the sentence objects |is| and |as|.

With mini.ai, `a` and `i` are mapped globally as well: type `S` within
'timeoutlen', otherwise mini.ai takes the `a` or `i` and rejects `S`.

To turn them off: >lua
    vim.g.asciidoc = { textobjects = { enable = false } }
<
Set this before the plugin loads (for example in lazy.nvim's `init`).

HEALTH CHECK                                    *asciidoc.nvim-health*

Run `:checkhealth asciidoc` to verify the setup. Checks:

1. Neovim version >= 0.11
2. `asciidoc-lsp` binary in `$PATH` (with version)
3. Treesitter ABI version
4. Treesitter parser `asciidoc` installed
5. Treesitter parser `asciidoc_inline` installed
6. nvim-treesitter plugin available (optional)
7. Every loaded asciidoc buffer with `asciidoc-lsp` attached: buffer path,
   client name and `root_dir`. Warns when the buffer path is not the file's
   real path (opened through a symlink).
8. `inotifywait` executable (Linux only), see
   |asciidoc.nvim-file-watching|.

==============================================================================
DEBUGGING                                          *asciidoc.nvim-debug*

                                                          *:AsciidocDebug*
:AsciidocDebug
    Ask `asciidoc-lsp` how it resolves the cursor position in the current
    buffer (`asciidoc.explainPosition`) and show the report as Markdown in
    a scratch buffer. The report lists the raw and canonical file path, the
    workspace root, the reference under the cursor, how it resolves (per
    attribute layer for attributes) and the known attributes with their
    source. Each call replaces the report in the same buffer and window.
